# Contributing to Tulip

This guide covers the build system, repository structure, and development workflows for contributors.

## Repository Structure

```
tulip/
├── cmd/
│   └── goreleaser/          # Goreleaser configuration generator
├── distributions/
│   └── tulip/               # Tulip distribution configuration
│       ├── manifest.yaml    # Component manifest (source of truth)
│       ├── config.yaml      # Default runtime configuration
│       ├── Dockerfile       # Container image definition
│       ├── tulip.service    # systemd service file
│       ├── tulip.conf       # systemd environment file
│       └── _build/          # Generated by ocb (not committed)
├── scripts/
│   ├── build.sh             # Build script
│   └── generate-goreleaser.sh
├── test/                    # Test scripts and utilities
├── Makefile                 # Build automation
└── go.mod                   # Go module definition
```

## Prerequisites

- Go 1.22 or later
- OpenTelemetry Collector Builder (ocb) -- automatically installed by the Makefile to `~/bin/ocb`
- [GoReleaser](https://goreleaser.com/install/) (optional, for releases and packaging)

## Build Commands

| Command | Description |
|---|---|
| `make build` | Generate sources + compile binary |
| `make generate-sources` | Generate source code only (no compilation) |
| `make generate` | Generate sources + goreleaser config |
| `make test` | Run tests |
| `make docker` | Build a local Docker image (`tulip:local` by default) |
| `make ci` | Full CI workflow (check + build + test + goreleaser validation) |
| `go fmt ./...` | Format Go code |

The compiled binary is output to `distributions/tulip/_build/tulip`.

## Development Workflow

1. Edit `distributions/tulip/manifest.yaml`
2. `make generate` (regenerates sources and goreleaser config)
3. `go mod tidy`
4. `go fmt ./...`
5. `make test`

## Adding or Updating Components

**To add a new component:**

1. Edit `distributions/tulip/manifest.yaml`
2. Add the component with its gomod path and version under the appropriate section
3. `make generate`
4. `go mod tidy`
5. `make build`
6. `make test`

**To update component versions:**

1. Edit `distributions/tulip/manifest.yaml` -- update version numbers
2. `make generate`
3. `go mod tidy`
4. `make test`

All OpenTelemetry components must use compatible versions. Contrib and core components version together.

## Build System Architecture

The build system is manifest-driven:

```
manifest.yaml -> ocb -> _build/*.go -> go build -> binary
```

1. **`manifest.yaml`** is the single source of truth for component selection and versions
2. **ocb** reads the manifest and generates Go source code in `_build/`
3. **`go build`** compiles the generated code into the final binary

Files in `_build/` are generated and should not be manually edited.

## Goreleaser Configuration

The `.goreleaser.yaml` in `distributions/tulip/` is **generated**, not manually edited:

```bash
make generate-goreleaser
```

To modify release configuration, update the generator templates in `cmd/goreleaser/`.

## Testing

```bash
# Full CI workflow
make ci

# Test single distribution
./test/test.sh -d tulip
```

The test system builds the distribution, starts the collector with a test config, generates test traces, verifies they are processed, and cleans up.

## CI/CD

**Continuous Integration (`ci.yaml`):**
- Triggered on push to `main` and on pull requests
- Runs `make ci`

**Release (`release-tulip.yaml`):**
- Triggered when a GitHub release is published
- Builds multi-platform binaries, packages (deb, rpm, apk), and container images
- Publishes to GitHub Releases and GitHub Container Registry
- Supported platforms: Linux (amd64, arm64), macOS (amd64, arm64)
